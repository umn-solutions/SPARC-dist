Project wizard fields

Inferred purpose is the likely intent behind each field. Actually drives is what the application does with the value. Question marks where the two may not match and a business answer is needed.

Step 1: Role

FieldSP columnInferred purposeActually drivesQuestion
Role Role Does our team own delivery (Leading) or support another team's (Contributing)? Which step 2 fields appear; forces Access level to Internal for Contributing; enables P4P PM If Contributing means supporting someone else's project, should linking to that project be required? The screen says Contributing projects inherit dates and access from the leading team, but the Contributing form has no Umbrella field and nothing is inherited. The link can only be added later in the Edit tab.

Same classification twice with two vocabularies.
Access levelLeading only AccessLevel Confidentiality Core of visibility. Defaults to Internal. Confidential can never be changed back Is Internal the right default? It hides the project from non-P4P users. The wizard shows the raw value "NoRestriction"; the Access tab shows "Open — no restriction".
GDPR classificationLeading only GDPRClassification Type of personal data handled Stored, shown and exported only No "no personal data" option: all three values (CPD, OPD, SPD) assume personal data, and CPD is pre-selected, so nobody actually decides it. Contributing projects get no value.
Tech ProjectTech only TechProject Technology or platform used Stored and exported "Tech Project" reads like a yes/no; it is really "Technology". Single choice only: what about projects using several technologies? Overlaps with Sub Category.
Tech PhaseTech only TechPhase Delivery stage (Business Case, Framing, Discovery, Dev, CM, Live) Stored and exported Overlaps Status (Pipeline is roughly Business Case/Framing). Why do only Tech projects have a phase? No history of phase changes. The spec says Contributing gets only Tech Project; the form shows both.
Umbrella ProjectLeading only UmbrellaProgram (title), LinkedPrograms (ID) Parent program or project Tree view, program children, overview The stored title goes stale when the parent is renamed. LinkedPrograms also holds project IDs. Only one parent is possible, although the schema describes a list.
Start date StartDate Planned start Start of the capacity window; also embedded in the project ID Optional. Empty means the project counts in every past month. No check that end is after start.
Expected end date ExpectedEndDate Planned finish End of the capacity window; overdue open projects stay counted in the current month The form says an empty end date is inherited from the umbrella project. Nothing does this, and programs have no dates to inherit. An empty end date is open-ended, so the project counts against capacity in every future month.

Set automatically

  • UUID: PROJ_NNNN_ddmmyyyy, using the start date and a random 4-digit number, with no uniqueness check.
  • SubmittedBy, SubmittedByEmail: the creator keeps owner and close rights permanently, even after leaving the team.

Not on the form (Edit tab only)

TargetType, TargetValues, TargetScope, AchievedValue, AchievedDate, Validated, NpsScore, ReviewComments, ClientFeedback, Improvements, CloseDate.
